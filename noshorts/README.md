# NoShorts 0.2 — исходники собственной Android APK

Приложение для Google Chrome на Android. Постоянное правило: `youtube.com/shorts`.
Дополнительные правила задаются как `домен/путь`; запись одного домена блокирует весь сайт.
Обычные страницы YouTube разрешены по умолчанию.

## Что изменено относительно первого прототипа

- Убраны эвристики по словам Shorts, comments, remix и другим текстам страницы.
- Решение принимает проверка домена и пути текущего адреса Chrome.
- Не совпадают `youtube.com.evil.example`, Google-поиск по Shorts и Shorts в параметрах обычного видео.
- Учитываются границы пути: `/shorts` блокируется, `/shortsFake` — нет.
- Проверка продолжается после Back; нет периода, когда распознавание отключено из-за cooldown.
- После обнаружения заблокированная страница остаётся закрыта экраном, даже если адрес скрыт.
- Экран блокировки убирается при уходе из Chrome. Есть выход на фиксированную главную YouTube.
- Сохранение дополнительных правил применяет их к работающей службе.
- Нет таймеров, временного разрешения, INTERNET permission, телеметрии и сохранения истории URL.

## Реальный статус

Это **исходники, не собранная APK**. Проверены Java-модуль правил и состояние блокировки.
Android-сборка, lint и работа на Samsung S24 Ultra ещё не проверены: в текущей среде нет Android SDK.
Workflow для сборки включён, но здесь он не запускался.

Не считать этот пакет доказательством «работает без пропусков». Обычная APK не получает доступ
к сетевым запросам и истории навигации другого приложения. Когда Chrome не отдаёт актуальный
полный URL через Accessibility, новая страница Shorts может остаться нераспознанной.
Если Chrome отдаёт только домен без пути, он не позволяет отличить обычное видео от Shorts.
Уже обнаруженная блокировка остаётся закрытой до подтверждённого разрешённого URL или перехода
на фиксированную главную; при скрытом адресе это может закрывать уже разрешённую страницу.

## Сборка

Android Studio: открыть папку проекта, установить Android SDK 35 и синхронизировать Gradle.
Используется Android Gradle Plugin 8.7.3, Gradle 8.9, Java 17. Gradle wrapper не включён.

```bash
gradle :core:verifyRules :app:lintDebug :app:assembleDebug
```

APK будет в `app/build/outputs/apk/debug/app-debug.apk`.
Либо загрузить содержимое этой папки в отдельный GitHub-репозиторий: включён workflow,
который запускает тесты, lint и создаёт артефакт APK. Репозиторий из этого чата не создавался.

После установки: открыть NoShorts → Включить службу → Accessibility → NoShorts — Chrome.
Для sideloaded APK Android может потребовать «Разрешить ограниченные настройки» в настройках приложения.
Samsung: проверить ограничения фоновой работы и список спящих приложений.
Сам факт установки без разрешённой службы не включает блокировку.

## Проверка ядра без Android

```bash
bash test-core.sh
```

Сценарии покрывают прямые Shorts URL, поддомены, percent encoding, dot segments,
ложные домены, search/watch URL, нераспознанный адрес, дополнительные пути, скрытие
адреса после обнаружения и возврат к обычной странице. Тесты не запускают Chrome.

## Почему одного allowlist/blocklist недостаточно

В самом Chrome есть `URLBlocklist` / `URLAllowlist`, включая правила с путём.
`chrome-policy-example.json` — пример таких правил; он **не устанавливает** их на Android.
Для их передачи Chrome нужны права Device/Profile Owner или делегированное управление
app restrictions. Обычный Device Admin, разрешение наложения и Accessibility этих прав не дают.
Work Profile управляет отдельным Chrome в профиле, а не личным Chrome.

У `URLBlocklist` есть документированная граница: правило не препятствует динамическому
JavaScript обновлять URL через History API. Поэтому блокировка прямого `/shorts` запроса
ещё не доказывает блокировку перехода в Shorts из открытого YouTube.

Обычный DNS/локальный VPN знает домены или соединения, но не зашифрованный HTTPS путь.
TLS interception потребовал бы сертификата, обработки QUIC и вмешательства в HTTPS;
при этом навигация SPA всё равно требует отдельной обработки. Здесь этого нет.

## Безопасность и область действия

Служба подписана на события стабильного Google Chrome, пакет `com.android.chrome`.
Из других окон проверяется только имя приложения, чтобы убрать покрытие при уходе из Chrome.
Текст других приложений не анализируется. Другие браузеры, Custom Tabs и YouTube app
не входят в заявленную область. Удаление/отключение службы, Safe Mode и остановка
процесса могут снять защиту. Нет контроля устройства, root, запрета удаления или сброса.
